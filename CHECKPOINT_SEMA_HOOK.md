# Retail initialization: two CreateSema calls and first SetSyscall (2026-10-18)

**Status:** verified original EE instructions and an experimental EE-kernel compatibility model, **not a playable native Windows game**. This is the new decompilation codebase; older PS2 recompilation experiments are references only.

## New verified path

- Earlier boot: execute actual retail startup through `SetupThread` (`0x001002FC`), blocked by missing BIOS. The subsequent `SetupThread`/`SetupHeap` path still requires a **test-only stack-pointer response** when continuing without a real kernel. No claim is made that the synthetic response matches the BIOS.
- `ae3_boot_semaphore_init.c`: execute original `JAL 0x0043FC08` at `0x0043FE60`; translate this routine and the original `0x00435AE0` syscall wrapper with correct `JAL`/`JR` delay slots, register writes, guest stack stores, and return-address restoration. Yield at each original `CreateSema` 0x40 syscall (`0x00435AE4`) without inventing a value. The EE descriptors are generated by the game's own `SW` instructions at stack addresses `0x01FFFF90` and `0x01FFFFB0` (with the test-only stack pointer). The game uses `max_count=1`, `init_count=1`, and option addresses `0x0072B940` and `0x0072B950`; other fields have preexisting stack contents and MUST NOT be presumed zero.
- When **external results** are supplied, original guest code writes the two returned semaphore IDs to `0x006A1EA8` and `0x006A1EAC`, restores its saved `$ra` and `$sp`, and returns to the genuine next JAL at `0x0043FE68`. The nested routine executes 34 more original instructions, including two guest `syscall` instructions. One-shot and single-instruction slicing produce the same saved CPU state and guest memory writes.
- `ae3_ee_sema_kernel.c`: experimental **opt-in** native kernel object pool (256 maximum), guest-visible sequential IDs, CreateSema descriptor validation, signal/poll count updates and safe rejection of invalid IDs. This is an **HLE compatibility subset**, not proof of BIOS scheduler semantics, error numbers or semaphore allocation order.
- `ae3_boot_hook_init.c`: continue through real `JAL 0x0043FD48` to first `SetSyscall 0x74` at `0x0043FE4C`. The game's actual registration request has syscall number `0x83` and guest handler address `0x0043FCC0` in the tested image. **No kernel syscall hook is installed**; execution yields at that boundary.

## Verification carried out

- Local native C builds of `test_boot_semaphore_init.c`, `test_ee_sema_kernel.c` and `test_boot_hook_init.c` pass `-Wall -Wextra -Werror`.
- All three pass AddressSanitizer and UndefinedBehaviorSanitizer, including checked guest memory faults, one-shot vs sliced execution, a 256-slot semaphore-pool capacity test, and permission to retry after correcting a memory fault.
- `ae3_boot_semaphore_init.c`, `ae3_ee_sema_kernel.c` and `ae3_boot_hook_init.c` compile into **Windows x64 COFF object files** with `clang-cl /W4 /WX` (not linked or tested as a Windows executable here).
- `ae3_boot_probe` default run still stops at the authentic unresolved `SetupThread` syscall. The explicit **two-part test mode** (`--test-kernel-fixture --test-sema-hle`) reaches the authentic `SetSyscall 0x74` boundary after a synthetic setup stack response and **experimental** semaphore model. It is not a game and does not render graphics.
- Original executable SHA-256: `5a8a73cf741b2e923f652f9bdf35d1798471ff31fb960b63ed010a78d1ac2d63`.

## Next real blockers

1. Implement real, reference-validated `SetupThread` and `SetupHeap` EE kernel behavior so the boot no longer relies on a synthetic stack return.
2. Implement `SetSyscall` hook table, syscall 0x83 handler/registration semantics, and the remainder of `0x0043FD48` and its nested callbacks.
3. Broaden dynamic R5900 code coverage and integrate IOP/SIF, VIF/GIF/GS, VU, disc, sound, and complete runtime before promising a playable build.

## Reproduce with your own unmodified retail executable

Linux:
```
AE3_ELF=/path/to/SCUS_975.01 bash BUILD_AND_TEST_LINUX.sh
./build/ae3_boot_probe "$AE3_ELF"
./build/ae3_boot_probe "$AE3_ELF" --test-kernel-fixture --test-sema-hle
```
Windows: run `BUILD_BOOT_DIAGNOSTIC_WINDOWS.bat` under a Visual Studio developer environment with `clang-cl`; set `AE3_BOOT_TEST_HLE=1` to opt in to the two synthetic/experimental test continuations. Defaults always stop at the unresolved authentic kernel syscall.
